# Inkforge 前台 UI 优化计划

> 状态：提案
> 日期：2026-08-08
> 审查范围：公开前台首页、文章列表页、文章详情页
> 审查依据：Leonxlnx/taste-skill `design-taste-frontend`，远端 `main` 提交 `3c7017d`

## 1. 设计判断

Reading this as: 面向 AI、工程与产品读者的编辑型博客前台，采用克制的编辑感与夜间阅读材质，优先保留现有品牌并做定向升级。

建议拨盘：

- `DESIGN_VARIANCE: 6`
- `MOTION_INTENSITY: 4`
- `VISUAL_DENSITY: 3`

后台属于高密度产品界面，不纳入本次营销页式重构规则。

## 2. 当前基线

### 2.1 已有优势

- 城市夜景背景、半透明面板和文章封面形成了明确的“夜读”识别。
- 文章列表页已有精选文章卡片，文章详情页已有封面 Hero、目录和阅读操作区。
- 深色模式层次完整，没有随机的区块主题翻转。
- 首篇文章图片使用 `priority`，跳过链接、焦点环、空状态和错误提示均已存在。
- 文章详情页的标题、元信息、目录关系清楚，适合继续作为品牌标杆页面。

### 2.2 已验证的问题

- 首页没有 `H1`，当前主内容由“AI 日报”和“最新文章”两个 `H2` 开始。
- 1440×900 桌面端：首页主内容从约 `y=272` 开始，顶部背景空间没有承担明确的信息任务。
- 390×844 移动端：AI 日报面板高度约 `391px`，第一篇最新文章标题被推到首屏之外。
- 移动端 AI 日报 5 条内容纵向堆叠，五条记录都显示相同的 `02:54` 时间。
- 首页最新文章全部使用相同的横向浮层卡片，内容节奏单一。
- `.reader-panel`、`.reader-card`、`.reader-feed-card`、`.reader-feature-card` 共享相近的边框、阴影和圆角，容易产生“卡片套卡片”。
- 全局本地字体仅声明 `500` 字重，但页面大量使用 `font-bold` 和 `font-extrabold`，存在合成粗体风险。
- 页面同时使用天空蓝和暖金作为强调色，交互重点不够集中。

## 3. 优化目标

1. 让首页在首屏内完成品牌说明、内容价值主张和首个阅读动作。
2. 让移动端首屏更快进入文章内容，降低 AI 日报对阅读流的阻塞。
3. 保留夜读品牌资产，同时减少浮层、阴影和装饰的重复。
4. 不改变 URL、主导航标签、表单字段、文章内容语气和既有统计事件。
5. 让首页、文章列表页、文章详情页共享同一套层级规则，而不是复制同一张卡片。

## 4. 分阶段任务

### P0：首屏与移动端入口

#### UI-01 首页增加编辑型主入口

现状：`src/app/(public)/page.tsx` 直接组合 AI 日报和最新文章，没有首页 `H1`。

建议：

- 增加一个唯一的首页 `H1`，使用站点名称或 `siteDescription`。
- 采用左侧文字、右侧真实文章封面的非对称结构。
- 保留一个主 CTA，例如“阅读精选”，不要增加重复的注册、联系或浏览按钮。
- 优先复用现有 `PostCardFeatured` 的视觉语言，避免新增通用 SaaS Hero。

验收标准：

- 首页只有一个可见 `H1`。
- 首屏出现品牌主张、真实视觉资产和明确阅读入口。
- 不改变现有导航标签、文章 slug 和 SEO 路径。

#### UI-02 重排移动端 AI 日报

现状：`HomeAiDailyStrip` 在移动端由五列布局退化为五条纵向内容。

建议：

- 桌面端保留五列结构。
- 移动端改为横向 `scroll-snap`，或展示 2 条摘要加“查看全部”。
- 将重复的时分格式改为日期，如“8月7日”。
- 移动端面板目标高度控制在 `150-190px`。
- 只保留一组“查看全部”意图，避免在同一屏重复 CTA。

验收标准：

- 390px 宽度下，AI 日报不超过约 `190px` 高。
- 第一篇最新文章的标题或明确入口出现在首屏内。
- 触控滚动、键盘焦点和 `prefers-reduced-motion` 状态可用。

#### UI-03 首页文章流改为精选首篇加紧凑列表

现状：`HomeLatestPosts` 中所有文章都使用同一横向卡片结构。

建议：

- 第一篇使用精选文章布局。
- 后续文章改为缩略图加标题的紧凑列表。
- 移动端缩略图高度控制在约 `88-112px`。
- 桌面端保留摘要和元信息，但移除每条卡片都占据的整条箭头操作区。

验收标准：

- 首页文章列表至少有两种明确的信息层级。
- 移动端首篇文章标题不被大图推到首屏之外。
- 列表仍保留文章、分类、阅读时长和阅读量等必要信息。

### P1：层级、空间和排版

#### UI-04 收敛卡片层级

建议建立以下规则：

- 精选文章、作者资料、AI 日报使用浮层卡片。
- 普通文章列表使用低对比背景、留白或稀疏分隔线。
- 统一主要圆角尺度，避免 `1.5rem` 与 `1rem` 无规则混用。
- 阴影只表达真实层级，不把每一行都抬离背景。

验收标准：

- 首页不再出现连续多个外观相同的高浮层卡片。
- 文章列表在浅色和深色模式下均能通过留白而非阴影分组。

#### UI-05 压缩首页背景留白并保留城市夜景

建议：

- 首页内容专用地减少顶部偏移约 `2-3rem`。
- 移动端背景高度由约 `42vh` 调整到约 `34-36vh`。
- 移动端关闭 `background-attachment: fixed`，降低滚动重绘成本。
- 保留城市轮廓作为品牌资产，但降低背景网格和装饰的对比度。

验收标准：

- 首页首屏不再出现没有内容承载的大片空白。
- 移动端滚动时没有背景抖动或明显掉帧。
- 背景图在深色和浅色模式下不压过正文和 CTA。

#### UI-06 处理字体字重映射

建议：

- 如果现有字体资产包含其他字重，补齐 `400/600/700`。
- 如果没有额外字重，减少 `font-extrabold`，使用字号、颜色和间距建立层级。
- 首页入口标题、列表标题、详情页标题分别定义排版角色。

验收标准：

- 中文标题不依赖浏览器合成粗体。
- 文章标题在浅色和深色模式下均保持清晰，不因过重而形成黑块。

### P2：品牌一致性与细节

#### UI-07 收敛强调色

- 天空蓝作为主要交互色、链接色和焦点色。
- 暖金只用于“精选”等语义状态。
- 分类色可以保留，但不应同时承担 CTA 或导航激活态。

#### UI-08 减少重复的标题竖线装饰

- 首页首个核心区块可保留蓝色竖线。
- 后续区块只用标题、间距和分隔关系建立层级。
- 不新增编号眉标、滚动提示、装饰文字带或重复状态点。

#### UI-09 保持有理由的动效

- 保留页面过渡、首屏进入和 CTA 反馈。
- 列表动效只用于说明阅读顺序，不给每个卡片增加独立循环动画。
- 所有强度高于轻微 hover 的动效都必须提供 reduced-motion 降级。

## 5. 推荐实施顺序

1. UI-01、UI-02、UI-03：先修首屏信息架构和移动端阅读入口。
2. UI-04、UI-05：再收敛卡片层级和背景空间。
3. UI-06、UI-07、UI-08：最后统一排版、颜色和装饰规则。
4. UI-09：在结构稳定后再微调动效。

## 6. 风险与约束

- 不修改 URL、导航标签、表单字段、文章 slug、法律文案和统计事件。
- 不把后台管理界面改造成营销页式布局。
- 不新增第三方依赖，优先复用现有组件和 token。
- 首页改造应保留现有错误、空状态和 SEO metadata 契约。
- 真实文章封面仍是首页和列表页的主要视觉资产，不使用 div 模拟产品截图。

## 7. 验证清单

- [ ] 首页存在且只有一个可见 `H1`。
- [ ] 1440×900 下首屏能看懂品牌、精选入口和最新内容。
- [ ] 390×844 下第一篇文章标题或入口可见。
- [ ] AI 日报移动端高度和内容数量符合目标。
- [ ] 浅色、深色模式对比度和层级一致。
- [ ] 键盘 Tab、跳过链接、焦点环和移动端菜单保持可用。
- [ ] `prefers-reduced-motion` 下不出现强制位移或循环动画。
- [ ] 相关组件测试、lint 和构建通过。
