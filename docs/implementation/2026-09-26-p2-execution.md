## 行为证据

- 健康接口正常均为 200、no-store，调用前后未新增健康路径审计记录。TCP 代理阻断数据库请求后，ready 在 2010 ms 返回 503；后续五次请求耗时 2–3 ms，始终只有一个未完成数据库连接。断库或配置缺失时 ready 为 503、live 为 200。初次健康查询耗时 434 ms。这是本地生产构建验证，不是 Docker 健康状态验证。
- 文章预热响应为 `x-nextjs-cache: HIT`。分类/标签改名后变为 MISS 并引用新路径，旧详情失效、目录同步；本次总耗时 176 ms。删除后的文章路径更新耗时 131 ms，均未等待 300 秒 TTL。
- HTTP 验证非法 slug、重复 slug、合法改名。保留原有 title/content 必填契约，没有为测试放宽请求校验。
- HTTP 验证父评论的文章、审核和删除状态。直接写入隔离库构造历史跨文章回复后，确认 API 与 SSR 页面均不展示；只删除本次拥有的记录。

## 审查后补修

1. AI 缓存失败不再中断后续项；持久化 article-info 验证快照，保留显式草稿语义。数据库、上传和资产写入故障不误记为模型业务失败。
2. Newsletter 草稿更新增加原子状态条件；无接受时间证据不填写 sentAt；首次核对和重放返回同事务完整计数；操作失败后也刷新打开的详情。对应回归先失败，修复后通过。
3. readiness 以底层原始查询实际结束释放标记，避免事务等待超时后积累连接申请。
4. 部署失败输出固定状态及有界日志信号，不输出原始日志或环境值。
5. E2E 清理使用实际通知类型 `aiTask`，验证通知接收人级联删除。

AI、Newsletter、readiness/日志维护及部署诊断均经独立 agent 复核，无剩余代码阻塞。
