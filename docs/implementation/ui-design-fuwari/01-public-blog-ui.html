记一次定时发布把数据库连接池占满的排查过程

本文提要（支持后台一键生成后人工微调） TL;DR
把外部图片下载与七牛上传移出数据库事务边界，并将默认单连接池调优为按环境自适应，彻底消除定时发布超时。

上周三早上看监控日志时，发现凌晨四点的定时发布任务报了一次连接池等待超时。奇怪的是当时整站并发极低，按理说一条简单的状态更新语句不可能卡满十秒。

顺着事务边界定位慢调用

翻看发布函数的调用栈才意识到，之前为了保证封面回填的原子性，把外部图片拉取直接写进了同一个交互式事务块里：

src/lib/publish-scheduled.ts 
// 先在事务外完成慢速 I/O，再进入短事务更新发布态
const uploadedCover = await ensurePostCoverOutsideTx(draft);
await prisma.$transaction(async (tx) => {
  await tx.post.update({ where: { id: draft.id }, data: { published: true, coverImage: uploadedCover } });
});

拆开事务后，单次锁连接时间从 4.2 秒降到了 6 毫秒，顺手也补了一条集成回归测试防止后续回退。
